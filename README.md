1  产品概述
Aurora 是一个可以独立运营的建站系统：主题负责界面、响应式、深浅色、SEO 与页面交互，业务能力（短信/社交登录、支付、余额、商品订单、投稿、会员）由 allin-pro-core 插件提供。两者分开的好处是——换主题不会丢业务数据，改界面不必动支付逻辑。
1.1  定位
· 内容站：文章、分类、专题、图库、幻灯片、相关推荐，面向长文阅读排版。
· 轻社区：板块（board）+ 问答（QA）两套内容形态，支持置顶、精华、投票与采纳。
· 会员制：VIP 等级、单篇购买、卡密兑换、余额与充值，一套价格体系覆盖三种变现。
· 轻电商：商品（规格 / 库存 / 限购 / 优惠码）+ 购物车 + 六通道支付回调。
· AI 增强：文章摘要、站内问答、后台写作助手，全部走同一个 OpenAI 兼容接口。
1.2  设计语言
整体按苹果官网的语言做：系统字体（-apple-system / PingFang SC）、大圆角卡片、毛玻璃浮层、克制的阴影与系统级缓动曲线。所有浮层遵循同一条规则——同时具备填充、高斯模糊与发丝描边，缺一项在浅色背景上就会「糊成一片」。
配色提供四套模式：跟随系统、浅色、深色、Spotify（深底 + 绿色强调）。切换结果存在浏览器 localStorage（键名 aurora-theme），通过 <html data-theme> 生效，首屏不闪白。
1.3  技术架构

图 1  请求链路：反向代理 → WordPress → 主题（UI）+ 插件（能力） → 数据库与外部服务
静态资源（CSS/JS/图片/字体）由反向代理直接输出并开启 gzip；动态请求交给 PHP-FPM。主题与插件都只通过 WordPress 提供的 API 读写数据，不直接连库，迁移时换域名、换服务器都不需要改代码。

3  前台功能详解
3.1  首页与幻灯片

图 2  首页首屏：幻灯片、公告条与分类入口
首页由若干区块组成，顺序可以在「后台 → 首页区块」里调整。幻灯片支持三种内容来源：
· 自动：先取置顶文章，再补最新文章，只收有特色图的；  适合日常更新
· 按文章编号：填 10, 7, 12，顺序即播放顺序，自动去重，最多 8 篇；  适合人工精选
· 手写一组：一行一张，竖线分隔「图片 | 标题 | 链接 | 描述」；  适合专题活动
编号模式下，输入框下方会实时列出每一条编号解析到的文章标题与编辑链接，找不到的编号标红，未发布或没有图的会注明「会被跳过」——填错当场就能看见。选中的文章优先用特色图，没有特色图时自动取正文第一张图。

图 3  首页下半部分：最新内容、板块精选与侧栏模块
3.2  板块与问答

图 4  板块列表：封面、帖子数、简介
板块是基于分类法 aurora_board 的内容聚合。每个板块可以标记置顶（_aurora_pinned）与精华（_aurora_featured），板块页会优先展示；首页「最新内容」只放纯文章，不混入板块帖，避免社区内容冲掉文章流。
把板块类型设为问答（_board_type = qa）后，帖子变成问题：回答就是评论，可以点赞/点踩（一人一票，投票记在 _qa_up / _qa_down / _qa_vote_<uid>），提问者可以采纳一个最佳答案，采纳后置顶显示。
3.3  图库

图 5  图库：独立素材池，瀑布网格 + 灯箱
图库与文章配图是两个池子：图库只展示在媒体库里勾选了「加入图库」的附件（_aurora_gallery = 1），文章里的插图不会混进来。这样图库的排版不会被长图、示意图打断，文章也不会因为图库的裁切规则变形。
3.4  搜索与站内问答

图 6  搜索结果页：命中标题高亮、分类筛选、分页
搜索框支持即时联想（AJAX），回车进入结果页。热门搜索词只取本站的标签，不引外部热词——站点越小，这越重要，否则会出现「热词全是别人的」。

图 7  问本站：用自然语言提问，先检索站内内容再回答，并列出引用来源
「问本站」先用关键词检索出相关文章，再把摘要与来源一起交给模型组织答案，所以回答能落到具体文章上；模型没配置时会提示去后台填密钥，不会报错崩页面。
3.5  文章页

图 8  文章页：正文、目录、作者栏、评分与打赏
文章页包含：阅读进度与目录、AI 摘要卡（无摘要不渲染）、评分（0 票不显示统计）、打赏（0 人不显示计数）、相关推荐、作者信息、评论与分享。开启付费墙后，未购买/未达等级的访客只能读到试读部分，购买入口按单篇价格结算。
「无数据不展示」是一条硬规则：摘要、评分、打赏、下载这些模块，数据为空时整块不输出，页面上不留空壳。
3.6  用户中心

图 9  用户中心：等级、积分、统计与功能入口
用户中心聚合了个人资料、我的文章、订单、积分流水、下载记录、站内消息与投稿状态。前台注册可以直接开放，也可以关掉只留登录；登录支持账号密码、短信验证码与社交账号。
3.7  会员与付费

图 10  会员中心：等级价格与权益对照
会员等级支持按月定价、权益对照、会员免费读单篇付费内容。三种变现方式可以并存：
· 订阅：按月付费的 VIP 等级；
· 单篇：指定文章单独标价，购买后可读 N 天（天数可配）；
· 卡密：后台生成卡密，用户在前台兑换，兑换尝试有每小时的次数上限。
3.8  商品与结算

图 11  商品页：规格、库存、限购、优惠码与结算入口
商品支持多规格（尺寸 / 颜色等组合各自定价与库存）、库存扣减、限购（按已支付订单 + 购物车数量合计）、优惠码与运费说明。结算页价格一律以服务端计算为准，前端只做展示——任何价格、档位都不从浏览器取值。
下单后进入支付：六个通道按「已配置优先」的顺序出现，未配置密钥的通道自动切到沙箱，演示流程照样能走完，不会因为缺密钥让访客卡在支付页。
3.9  投稿与写作

图 12  前台投稿：栏目、标题、正文与提交说明
投稿页可以设定最低等级与提交后的状态（待审 / 直接发布）。提交后进入后台审核队列，通过即发布，退回会带上理由。

图 13  前台写作：富文本工具栏、分类标签、45 秒自动保存
写作页是前台编辑器：标题、正文、分类、标签，支持加粗、引用、代码、列表、链接与图片，每 45 秒自动保存草稿，也能用快捷键保存或提交审核。
3.10  网址导航与热点

图 14  网址导航：分组卡片、自动抓取的站点图标
导航页按分组陈列外链，保存时自动抓取站点 favicon 并本地缓存，避免第三方图床挂掉后一片空白；每行列数可配，首页可以只放一个入口。

图 15  热点榜：按热度排序的榜单，可开首页卡片与文章侧栏
热点是聚合榜单：按浏览量/评论数加权排序，可设置缓存时长（分钟），首页与文章侧栏各有一个开关，关掉就不占位。
3.11  深色模式、响应式与 PWA

图 16  深色模式：背景、卡片、文字与强调色整体切换
深浅色不是简单反色：卡片、描边、阴影、图表与代码块都有各自的深色取值，浮层在深色下会自动降低透明度并加深边框，保证「玻璃」仍然可读。

图 17  手机端首页：单列卡片、底部导航栏

图 18  手机端板块页：底部 Tab 导航
响应式按 1024 / 768 / 640 三个断点收敛：桌面三栏 → 平板两栏 → 手机单列，手机端启用底部导航栏，页脚桌宠在 640px 以下整块隐藏，图片懒加载，不再下载。
PWA 提供 manifest 与 Service Worker：加到主屏后独立窗口打开，已访问页面可离线查看。注意 Service Worker 只在 HTTPS（或 localhost）下生效，HTTP 访问时浏览器直接忽略，不影响正常浏览；后台、登录页与 AJAX 请求永远不走缓存。

6.3  性能
· gzip 覆盖 CSS / JS / JSON / SVG / WOFF2：main.css 164KB → 31.6KB，main.js 67KB → 15.8KB。
· 图片全部 width/height 声明，配合 lazy loading，首屏不跳动。
· 列表查询关闭 no_found_rows、按需取字段；首页排除测试夹具与板块帖。
· 静态资源带版本号（?v=版本），升级后浏览器自动取新文件，不需要手动清缓存。
6.4  安全
· 全部表单带 nonce，后台操作校验 manage_options 能力。
· 匿名请求不暴露 /wp/v2/users，用户枚举接口整段移除。
· 验证码与频率限制可分别作用于登录、评论、投稿、支付回调。
· 密钥、商户证书、SMTP 密码只存服务端，页面只显示末四位。
· 支付回调验签 + 幂等；金额与档位一律服务端计算。
6.5  SEO
每页输出标题模板、描述、canonical、Open Graph 与结构化数据（Article / BreadcrumbList），自动生成站点地图与 favicon（内联 SVG，另带一份多尺寸 .ico）。
6.6  AI 接入
摘要、问本站、写作助手共用同一个入口函数与同一套配置：接口地址 + API Key + 模型名。没填密钥时按钮置灰并提示去设置，不报错、不消耗额度；摘要按文章缓存，重复访问不再请求模型；写作助手只生成草稿，不会自动写入数据库。

8  安装教程
下面以 Ubuntu 24.04 + Nginx + PHP 8.3 + MariaDB 为例，从一台空服务器装到可以访问。已有 WordPress 的站点可以直接跳到 8.4。
8.1  准备
· 一台能 SSH 的服务器，域名已解析到服务器 IP（没有域名可先用 IP 测试）。
· root 或 sudo 权限。
· 本地准备好 aurora-theme-2.5.15.zip 与 allin-pro-core-0.4.0.zip。
8.2  安装 Nginx、PHP 与数据库
sudo apt update
sudo apt install -y nginx mariadb-server unzip curl
sudo apt install -y php8.3-fpm php8.3-mysql php8.3-curl php8.3-gd \
     php8.3-mbstring php8.3-xml php8.3-zip php8.3-intl php8.3-bcmath \
     php8.3-imagick php8.3-opcache
sudo systemctl enable --now nginx php8.3-fpm mariadb

建库与账号（把密码换成自己的）：
sudo mariadb -e "CREATE DATABASE aurora DEFAULT CHARACTER SET utf8mb4;"
sudo mariadb -e "CREATE USER 'aurora'@'localhost' IDENTIFIED BY '换成你的密码';"
sudo mariadb -e "GRANT ALL ON aurora.* TO 'aurora'@'localhost'; FLUSH PRIVILEGES;"

8.3  部署 WordPress
cd /var/www
sudo curl -O https://cn.wordpress.org/latest-zh_CN.tar.gz
sudo tar xzf latest-zh_CN.tar.gz && sudo mv wordpress aurora
sudo chown -R www-data:www-data /var/www/aurora
cd /var/www/aurora
sudo -u www-data wp config create --dbname=aurora --dbuser=aurora \
     --dbpass="换成你的密码" --dbhost=localhost --locale=zh_CN
sudo -u www-data wp core install --url="https://你的域名" \
     --title="站点名" --admin_user=admin --admin_password="强密码" \
     --admin_email=you@example.com

没有 wp-cli 时，也可以浏览器访问域名走五步安装向导，效果一样。
8.4  上传主题与插件
方式一（推荐，后台上传）：登录后台 → 外观 → 主题 → 上传主题 → 选 aurora-theme-2.5.15.zip → 启用；插件 → 安装插件 → 上传插件 → 选 allin-pro-core-0.4.0.zip → 启用。
方式二（命令行）：
sudo -u www-data wp theme install /path/aurora-theme-2.5.15.zip --activate
sudo -u www-data wp plugin install /path/allin-pro-core-0.4.0.zip --activate

8.5  伪静态、上传目录与权限
Nginx 站点配置示例（按域名与 PHP 版本调整）：
server {
    listen 80;
    server_name 你的域名;
    root /var/www/aurora;
    index index.php index.html;
    client_max_body_size 32m;
 
    gzip on;
    gzip_types text/css application/javascript application/json \
               image/svg+xml font/woff2;
 
    location / { try_files $uri $uri/ /index.php?$args; }
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }
    location ~ /\.(?!well-known) { deny all; }
}

保存后执行 sudo nginx -t && sudo systemctl reload nginx，再到后台「设置 → 固定链接」选「文章名」或自定义 /%post_id%.html 并保存，伪静态才会生效。
权限只需要两条：目录 755、文件 644，属主 www-data。不要把整站设成 777。

现象	排查方向
首页 500 / 白屏	看 /var/log/nginx/error.log 与 php8.3-fpm 日志；多为扩展缺失或目录权限不对

11  常见问题
Q  能不能只用主题、不装插件？
可以。文章、板块、图库、幻灯片、会员等级、积分、AI 这些都在主题里；插件补的是短信/社交登录、支付通道、余额充值、提现与分销。不装插件时结算会提示未配置支付方式。
Q  主题会不会和别的插件冲突？
主题只用自己的命名空间（aurora_*）与独立设置表，不改 WordPress 核心文件，也不 hook 别人的后台页。已知冲突集中在缓存插件与图片压缩插件：它们会改写 CSS/JS 路径，遇到样式异常先关掉这两类插件试一次。
Q  幻灯片想同时放「指定文章 + 自动补位」怎么办？
目前三种来源互斥。要混排，用「按文章编号」把想要的几篇都填进去，不足的部分再补编号，顺序完全按你填的来。
Q  手机端为什么看不到桌宠？
640px 以下整块隐藏，同时图片懒加载不下载。这是有意的：手机上页脚本来就窄，人物会挤掉文字。
Q  AI 不填密钥能用吗？
能用。摘要卡不渲染、问本站与写作助手按钮置灰并提示去设置，其余功能不受影响；填了密钥后按文章缓存摘要，不会重复计费。
Q  会员和单篇购买能同时开吗？
能。会员免费读的规则可以指定「哪个等级以上免费」，未达等级的访客看到单篇购买入口，购买后可读天数单独配置。
Q  升级会不会丢设置？
不会。设置在 theme_mods_aurora，数据在数据库；覆盖主题文件不影响两者。唯一的例外是手动改过主题文件——那种改动会被覆盖，建议用子主题。
